# 支线栈契约（rigor-tutor 唯一权威）

> **单一事实源。** "遇术语卡壳开递归支线、理解了能递归回去"这件事怎么做，**只在本文件定义**。
> 一句话：**支线是一条显式栈，压进去就一定要能弹回来，而且这条栈必须落盘**——否则上下文一压缩，"回得去"就没了。

## 1. 栈数据结构

维护一条**支线栈**，每个栈帧是一条"没讲完的话题"，至少含：

| 字段 | 含义 |
|---|---|
| `topic` | 这条支线在讲什么（一个术语 / 一个子问题） |
| `parent` | 它是从哪个话题/断点开出来的（父帧的 topic + 断点在哪一步） |
| `status` | `open`（还没讲完）/ `closed`（学习者已确认理解） |

栈顶 = 当前正在讲的话题。**每压/弹一次栈，都要把这条栈的当前形态同步进落盘笔记**（§5）。

## 2. 压栈（什么时候开支线）

回答中遇到学习者**难以理解的术语 / 概念**时，先判"**这个术语是否真的在挡路**"：

- **在挡路**（不懂它就看不懂主线这一步）→ **压栈**，开一条支线，显式说："我们先离开主线补一下 `X`，讲完回到 `Y` 的第 2 步。"
- **不在挡路**（只是陌生名词、不影响理解主线逻辑）→ **不压栈**，一句话带过（"`X` 就是 …，先记住即可，后面用到再展开"），继续主线。

> 不判就压栈，会退化成 Yak shaving：每个陌生词都开一条支线，主线永远回不来。**只给"挡住理解"的术语开支线。**

## 3. 弹栈与重锚

支线讲完后，**必须等学习者确认"懂了"**（不是"听到了"）。确认方式二选一：

- 让他用一句话复述这个术语的关键；
- 或让他在主线上下文里用一次。

**确认通过 → 弹栈**，并**用一句话重锚**回父话题的断点："回到 `Y`：我们刚才停在 `Y` 的第 2 步（你问的是 …），现在有了 `X`，这一步是 …"。

**没通过 → 不弹栈**，回到 §2 再判：是这条支线里的**又一个**术语在挡路（再压一层），还是这条支线本身梯度太陡（拆细，不压新栈）。

## 4. 深度控制（防无限递归）

- **每压一层栈，都要能说出"这条支线是为了主线哪一步"**——说不出的，不压。
- **连续压栈超过 3 层**（栈深度 > 3）时，停下来做一次"**是否在兜圈子**"检查：这些支线最终都指向同一个还没懂的概念吗？是 → 说明问题不在这些术语，而在更上游的一个**前置概念**——退回去，直接攻那个前置，而不是继续往下钻。
- 支线本身也要遵守分层契约（rigor-contract §3）：严谨表述 + 直觉 + 回译，不能因为是支线就偷工减料。

## 5. 栈的落盘形态

栈必须落盘，否则弹栈的"返回路径"只活在对话里，会被上下文压缩掉。落在**当前会话笔记**里（见 vault-spec §5），形态用**缩进列表**或**嵌套 callout**：

```markdown
- 主线：期权定价为什么要风险中性测度
  - 支线：风险中性测度是什么（open）
    - 支线：等价鞅测度是什么（closed）
  - （回到主线：风险中性测度 已讲完，回第 2 步）
```

- 每压/弹一次，就更新这段（**不攒到最后**，会话边界 = 记录边界，见 vault-spec §7）。
- 会话结束时，栈顶未闭合的支线写进「下次入口 → 待办」，下次接续从这里继续。
