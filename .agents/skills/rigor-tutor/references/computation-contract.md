# 计算核验契约（rigor-tutor 唯一权威）

> **单一事实源。** "数值必须是计算机计算的结果"这件事怎么做，**只在本文件定义**。
> 一句话：**每个数字都要能从一条命令追溯到它的来源；跑不了的，要显式说没跑。**

## 1. 工具链与 bootstrap

- **符号推导**：SymPy（积分、求导、化简、解方程、极限）。
- **数值/统计**：NumPy、SciPy（随机模拟、分布、优化、线性代数）。
- **出图**：matplotlib（`Agg` 后端，写 PNG）。
- **LaTeX 校验**：KaTeX（Node），见 vault-spec §6。

**初始化**（新设备 / 首次使用必跑）：

```bash
python3 scripts/bootstrap.py            # 建 .tooling/venv + 装 Python 依赖 + npm 装 katex + 自检
python3 scripts/bootstrap.py --self-test # 只跑自检，不重装
```

bootstrap 会在仓库根创建 `.tooling/`（已 gitignore），包含 `venv/` 和 `node_modules/`。**`.tooling/` 不进仓库、不可移植**——换设备就重跑 bootstrap。

**跑计算的解释器**：`.tooling/venv/bin/python`。判断 `.tooling/venv` 是否存在；不存在或 import 失败 → 走 §5 退化。

## 2. 什么必须机器算（判定表）

| 出现这些 | 必须 | 工具 |
|---|---|---|
| 定积分 / 不定积分 / 级数和 | 符号核验 | SymPy |
| 求导 / 化简 / 展开 / 因式分解 / 解方程 | 符号核验 | SymPy |
| 概率 / 分布的分位数 / 期望方差 | 数值或符号核验 | SciPy / SymPy |
| 矩阵运算 / 特征值 / 伪逆 | 数值核验 | NumPy/SciPy |
| 优化 / 求根 / 拟合 | 数值核验 | SciPy |
| 蒙特卡洛 / 随机模拟 | 跑真实随机数 | NumPy |
| 任何"≈ 多少""等于多少""收敛到多少"的**具体数** | 必须跑 | 相应工具 |

**反例（禁止）**：报出一个 6 位小数却没有任何命令产生过它；说"模拟 10 万次收敛到 0.63"却从没跑过模拟。**凡是具体数，必须有产生它的命令。**

## 3. 出处格式（provenance）

回答和笔记里，每个"工具算出来的数"旁边都要写清来源，两种等价写法：

- 行内：`∫₀¹ x² dx = 1/3`（SymPy `integrate(x**2,(x,0,1))` → `1/3`）
- 脚注式：`E[X] = 2.501`（来源：`numpy.mean(sample)`，n=100000）

**格式要求**：`数值（工具 + 关键命令 → 原始输出）`。让"计算机算的"可审计，而不是一句"经计算"。

## 4. 可视化（先预测后验证，且必须真实渲染）

- 顺序：先让学习者预测 → 再给图 → 追问是否一致。
- 图用 matplotlib（`Agg`）渲染成 PNG，存到可引用的图目录（如 `<主题>/assets/figN.png`）。
- 聊天界面不渲染 Obsidian Charts/Dataview 代码块，所以图必须落成真实 PNG 或改用 LaTeX 表格/ASCII。
- 图不能替代思考，也不能替代 §2 的机器核验——图是"看"，核验是"算"。

## 5. 退化标注（环境跑不了时）

`.tooling/venv` 缺失、sympy/numpy 导入失败、或 katex 未装时，**不要悄悄退回心算**——那会让"算过"和"没算过"在记录里长得一模一样。必须：

1. 在回复里**明写**："本节数值未经机器核验"（或"本节 LaTeX 未经渲染校验"）；
2. 能补救就补救：提示先跑 `python3 scripts/bootstrap.py`；
3. 该数若仍要给出，标注「待核验」，不得当成确定结论。

> 一条检验式：**读者能不能区分"这条数机器算过"和"这条数 AI 口算"？** 分不出来，就是违约。
