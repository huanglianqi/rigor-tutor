# 落盘契约（rigor-tutor 唯一权威）

> **单一事实源。** rigor-tutor 怎么读写 Obsidian 学习库、写哪些文件、记什么、LaTeX 怎么保证能渲染、会话怎么交接，**只在本文件定义**。
> 与 the-tutor 的约定对齐但**命名空间隔离**：两个技能可在同一库共存，互不踩文件。

## 1. 通道：Obsidian MCP 首选，文件 I/O 退化

开场先探测：手头有没有 Obsidian MCP 工具（`obsidian_list_vaults` / `obsidian_read_note` / `obsidian_create_note` / `obsidian_edit_note` / `obsidian_search_vault` 等）。

- **有 MCP → 首选 MCP**：`obsidian_list_vaults` 拿 vault id；读用 `obsidian_read_note`（返回 etag），改用 `obsidian_edit_note` 带 `if_match`（etag 守卫防并发覆盖）；新建 `obsidian_create_note`；破坏性操作用 trash 模式。
- **没有 MCP → 退文件 I/O**，并明说一句："本会话无 Obsidian MCP，用文件直接读写，无 etag 并发守卫。"

## 2. 学习库根解析（顺序，命中即停）

1. 工作区即学习库（cwd 含 `.obsidian/` 或用户明说"就用这个库"）；
2. 学习者本会话给出路径 / 库名；
3. 都失败 → 直接问。不在磁盘上乱找，不另建新库。

> **解析成功后不写任何记录文件记住绝对路径**（跨设备必错）。每次会话重新解析；有 MCP 时用 `obsidian_list_vaults` 拿 vault id。**vault 永不进技能本体、永不进记录文件。**

## 3. 命名空间与目录结构

**只写自己的命名空间**，不碰库中其他笔记（但可用 wikilink 指向库内已有笔记、读它们的 frontmatter）：

```
<库>/问答/                      ← rigor-tutor 独占命名空间（与 the-tutor 的 <主题>/ 隔离）
  00-索引.md                   问答记录总索引（主题 → 笔记 的链接表）
  <主题>/
    <主题>-答疑-<日期>.md       每次答疑会话一篇（实时记录，见 §5）
    assets/                    图、算例 PNG
```

- 一个主题一个子目录；会话笔记命名带日期，方便按时间追。
- 与 the-tutor 同库时，各自用各自的命名空间（the-tutor 写 `<主题>/学习地图.md`，rigor-tutor 写 `问答/<主题>/`），**不互踩**；但可以 wikilink 互指（"这个概念的引导式推导见 [[学习地图]]"）。

## 4. 重要部分入选标准（记什么）

**只记"能启发理解的重要逻辑"，不记聊天全量。** 四类入选，缺一不可的原则是"由它能不能帮你以后理解"决定：

1. **严谨表述**：定义 / 定理 / 关键式子（带锚点，rigor-contract §1）。
2. **顿悟点**：让你"啊原来如此"的那一步关键逻辑（**agent 提议，学习者确认**）。
3. **计算结果的数值 + 出处**（computation-contract §3）。
4. **支线栈的路径**（branch-stack §5）。

**触发方式（混合）**：agent 在讲到一个关键点时**提议**"这条要不要记？"，学习者说"记下来"才写；学习者也可随时说"记一下这个"。

**不记**：寒暄、重复的追问、已经被更准表述覆盖的旧版本。

## 5. 笔记结构模板

会话笔记 frontmatter + 分节，`严谨表述` / `直觉` 用 Obsidian callout 区分，便于回顾：

```markdown
---
type: rigor-qa
topic: <主题>
date: <YYYY-MM-DD>
tags: [问答, <主题>]
---

# <主题> 答疑 <YYYY-MM-DD>

## 支线栈（当前状态）
- 主线：…（open）

## 严谨表述
> [!abstract] 严谨表述（锚点：弱）
> 定义/定理的 LaTeX。

## 直觉
> [!note] 直觉（类比，不是定义）
> 现实场景说明。回译：…（通过/修改后通过）

## 算例（数值带出处）
$\int_0^1 x^2\,dx = \tfrac{1}{3}$（SymPy `integrate(x**2,(x,0,1))` → `1/3`）

## 下次入口
- 停在哪 / 卡在哪 / 待办（未闭合支线、待核验项）
```

## 6. LaTeX 校验流程（写前必跑）

Obsidian 用 MathJax 渲染，但**"看起来对"不等于"能渲染"**。落盘前必须机器校验：

```bash
node scripts/latex_check.js "<笔记路径>"
```

- 校验器用 KaTeX 把每个 `$...$` / `$$...$$` 渲染一遍，**报错就不许落盘**，改到通过为止。
- 退出码 0 = 全部渲染通过；1 = 有公式渲染失败（会报出是哪个片段）。
- 常用坑：`\frac` 里忘写参数、`$` 不配对、用了 MathJax 有而 KaTeX 无的宏、`&` 对齐符裸露、中英文与 `$` 粘连。校验器抓的就是这些。
- 环境没装 katex → 先跑 `python3 scripts/bootstrap.py`；仍不行 → 按 computation-contract §5 显式标注"本节 LaTeX 未经渲染校验"。

## 7. 会话边界与下次入口

- **会话边界 = 记录边界**：推进到哪里就写到哪里，不攒到最后一次写。
- **「下次入口」必填**：停在哪 / 卡在哪 / 待办（未闭合支线、`待核验` 项）。只写"待补"的空壳不算写完。
- 接续时重读 `00-索引.md` 与对应会话笔记的「下次入口」，**不要靠旧对话记忆**（会被压缩掉）。
- AI 做不到新建/归档会话，只能提醒 + 给一段可复制的接续开场白。
